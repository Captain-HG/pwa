## 2. D1 表结构

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,          -- pbkdf2_sha256$<迭代次数>$<盐b64>$<哈希b64>
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

CREATE TABLE sessions (
  id           TEXT PRIMARY KEY,        -- 令牌的 SHA-256（hex），不存令牌原文
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at   INTEGER NOT NULL,
  last_seen_at INTEGER NOT NULL,
  expires_at   INTEGER NOT NULL,
  user_agent   TEXT,
  ip           TEXT
);
CREATE INDEX idx_sessions_user ON sessions(user_id);

CREATE TABLE login_attempts (
  key          TEXT PRIMARY KEY,        -- 'ip:<ip>' 或 'user:<username>'
  fail_count   INTEGER NOT NULL,
  locked_until INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

CREATE TABLE records (
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  entity     TEXT NOT NULL,             -- transactions / categories / accounts / budgets
  id         TEXT NOT NULL,
  updated_at INTEGER NOT NULL,          -- 客户端修改时间，用于冲突判定
  deleted    INTEGER NOT NULL DEFAULT 0,
  rev        INTEGER NOT NULL,          -- 服务端递增版本号，用于增量拉取
  data       TEXT NOT NULL,             -- 记录 JSON
  PRIMARY KEY (user_id, entity, id)
);
CREATE INDEX idx_records_rev ON records(user_id, rev);
```

所有时间为毫秒时间戳。

## 3. 鉴权

### 3.1 中间件流程（`functions/_middleware.ts`）

```
请求 → 路径在公开名单？（图标、manifest、/api/auth/login）→ 放行
     → 路径为 /login？→ 已登录则 302 到 /，否则返回登录页
     → 读取 Cookie __Host-sid → 计算 SHA-256 → 查 sessions（未过期）
         ├─ 无效：/api/* 返回 401 JSON；/sw.js 返回「自我注销」脚本（见下）；其他返回 302 /login
         └─ 有效：
              写接口（非 GET/HEAD）校验 Origin 与 Content-Type，不符返回 403
              ctx.data.session = { id, userId, username }
              放行 → 若需续期，在响应上追加 Set-Cookie
```

**`/sw.js` 特殊处理**：Service Worker 脚本不允许经过重定向。若未登录时把 `/sw.js` 也重定向到登录页，已安装的旧版本（或会话过期的设备）检查更新会失败，永远停在缓存页面。因此未登录请求 `/sw.js` 时返回 `server/swKillSwitch.ts` 中的脚本：安装后清空离线缓存、注销自己并刷新页面，之后请求走网络进入登录页；本地 IndexedDB 数据保留，登录后照常同步。

公开名单：`/favicon.svg`、`/apple-touch-icon.png`、`/pwa-192.png`、`/pwa-512.png`、`/manifest.webmanifest`、`/api/auth/login`。

### 3.2 会话

| 项 | 规则 |
|---|---|
| 令牌 | 32 字节随机数，base64url |
| Cookie | `__Host-sid=<令牌>; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=7776000`（90 天） |
| 存储 | `sessions.id = SHA-256(令牌)` |
| 续期 | `last_seen_at` 距今超过 1 小时才更新；剩余有效期不足 60 天时延长到 90 天并重发 Cookie |
| 退出 | 删除当前会话记录，返回清除 Cookie 的 `Set-Cookie` |
| 改密码 | 删除该用户除当前会话外的所有会话 |

### 3.3 密码

- 格式：`pbkdf2_sha256$100000$<16 字节盐 base64>$<32 字节哈希 base64>`。
- 校验：解析出迭代次数与盐重新计算，常量时间比较。
- 用户不存在时，用固定的假哈希走一遍计算，再返回同样的错误「用户名或密码错误」。
- 新密码至少 8 位。

### 3.4 登录限流

- 登录前检查 `ip:<IP>` 与 `user:<用户名>` 两个键，任一 `locked_until > now` 则返回 429「尝试次数过多，请 N 分钟后再试」。
- 失败：两个键 `fail_count + 1`；达到 5 次时 `locked_until = now + 15 分钟` 并将计数清零。
- 成功：删除两个键。
- 计数在 15 分钟无新失败后视为过期（按 `updated_at` 判断）。

## 4. 接口

所有接口返回 JSON；错误统一为 `{ "error": "中文说明" }`。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/auth/login` | `{ username, password }` | 200 `{ username }` + Set-Cookie；401；429 |
| POST | `/api/auth/logout` | — | 200 `{ ok: true }` |
| GET | `/api/auth/me` | — | `{ username }` |
| POST | `/api/auth/password` | `{ oldPassword, newPassword }` | `{ ok: true }`；400 |
| GET | `/api/auth/sessions` | — | `{ sessions: [{ id, current, createdAt, lastSeenAt, userAgent }] }` |
| DELETE | `/api/auth/sessions/:id` | — | `{ ok: true }`；不能删除当前会话（用退出登录） |
| POST | `/api/sync/push` | `{ changes: Change[] }` | `{ applied: number }` |
| GET | `/api/sync/pull?since=<rev>&limit=<n>` | — | `{ records: Remote[], cursor: number, hasMore: boolean }` |

```ts
interface Change {           // push 上行
  entity: 'transactions' | 'categories' | 'accounts' | 'budgets';
  id: string;                // ≤ 64 字符，且等于 data.id
  updatedAt: number;
  deleted: boolean;
  data: object;              // 完整记录，JSON 后 ≤ 16 KB
}
interface Remote extends Change { rev: number }   // pull 下行
```

- push 单次最多 500 条，超出返回 400；客户端按 200 条分批。
- pull 的 `limit` 默认 500，最大 1000。

### 4.1 写入 SQL（Last-Write-Wins）

一次 push 的所有语句放在一个 D1 `batch` 中（原子执行）：

```sql
INSERT INTO records (user_id, entity, id, updated_at, deleted, data, rev)
VALUES (?1, ?2, ?3, ?4, ?5, ?6,
        (SELECT COALESCE(MAX(rev), 0) + 1 FROM records WHERE user_id = ?1))
ON CONFLICT (user_id, entity, id) DO UPDATE SET
  updated_at = excluded.updated_at,
  deleted    = excluded.deleted,
  data       = excluded.data,
  rev        = excluded.rev
WHERE excluded.updated_at > records.updated_at;
```

旧数据（`updatedAt` 不大于云端）不会覆盖，`applied` 只统计实际写入的条数。

## 5. 客户端变更追踪

### 5.1 本地库 v2

```ts
db.version(2).stores({
  transactions: 'id, occurredAt, [type+occurredAt], categoryId, accountId, updatedAt, dirty',
  categories:   'id, type, sort, dirty',
  accounts:     'id, sort, dirty',
  budgets:      'id, month, [month+categoryId], dirty',
  settings:     'key',
}).upgrade(...)   // 已有记录：dirty = 1；分类/账户/预算补 updatedAt = 1
```

四张同步表的记录新增 `updatedAt: number`（分类、账户、预算原先没有）与 `dirty: 0 | 1`。

### 5.2 Dexie 钩子（`db/tracking.ts`）

| 钩子 | 本地写入 | 应用云端数据（事务带 `remote` 标记） |
|---|---|---|
| creating | 未指定 `updatedAt` 时补当前时间；`dirty = 1` | 原样写入，`dirty = 0` |
| updating | 追加 `updatedAt = now`、`dirty = 1`（修改里显式带了 `updatedAt` 则保留） | 不追加 |

- 预置分类与默认账户以 `updatedAt = 0` 写入：新设备推送时不会覆盖云端已改过的同名预置项。
- 每次本地写入提交后，调用 `scheduleSync()`（2 秒防抖）。

## 6. 同步算法（`sync/sync.ts`）

```
syncNow()（同一时间只运行一个，并发调用复用同一个 Promise）
  1. push：
     收集四张表中 dirty = 1 的记录 → 每 200 条一批 POST /api/sync/push
     每批成功后，在 remote 事务中：若本地记录 updatedAt 仍等于推送时的值 → dirty = 0
     （推送期间又被修改的记录保持 dirty，下次再推）
  2. pull：
     cursor = settings.syncCursor ?? 0
     循环 GET /api/sync/pull?since=cursor，直到 hasMore = false：
       在 remote 事务中逐条处理：
         本地不存在                         → 写入（dirty = 0）
         本地 dirty 且 本地.updatedAt > 云端 → 跳过（保留本地，下次推送）
         否则                               → 覆盖（dirty = 0）
       保存 cursor
  3. 记录 lastSyncAt、清除错误；失败时记录错误信息
```

- 触发：启动、本地写入（防抖 2 秒）、`visibilitychange` 回到前台、`online` 事件、每 5 分钟。
- 离线（fetch 抛 TypeError）：记为「离线，稍后重试」，不弹提示。
- 收到 401：执行「本机登出」（见 §7.3）。

## 7. 前端

### 7.1 API 客户端（`api/client.ts`）

- `api<T>(path, { method, body })`：同源 `fetch`，自动加 `Content-Type: application/json`。
- 401 → 调用 `handleUnauthorized()`；其他非 2xx 抛出带 `error` 文案的异常。

### 7.2 账号与同步页（`#/account`）

```
账号        me
──────────────────────
同步状态     上次同步 2 分钟前 / 同步中… / 离线，稍后重试
待同步       0 条
[ 立即同步 ]
──────────────────────
登录设备
  iPhone · 本机           最近活动 刚刚
  Windows · Edge          最近活动 3 天前   [移除]
──────────────────────
修改密码  ›
退出登录（红色）
```

### 7.3 退出与本机登出

- **退出登录**：先 `syncNow()`；仍有待同步数据时二次确认 → `POST /api/auth/logout` → 本机登出。
- **本机登出**（退出或收到 401）：清空 IndexedDB 全部表 → 注销 Service Worker、删除 Cache Storage → `location.replace('/login')`。

### 7.4 其他页面调整

| 位置 | 调整 |
|---|---|
| 首页 | `BackupReminder` 替换为 `SyncReminder`：待同步 > 0 且距上次成功同步 ≥ 24 小时，或登录失效时显示 |
| 设置 | 顶部新增「账号与同步」；「清空所有数据」改为「清空所有流水」 |
| 备份 | 覆盖导入改为：本机流水全部软删除，再写入备份记录（`updatedAt = now`），随后同步 |
| PWA | Workbox `navigateFallbackDenylist` 加入 `/api/`、`/login`，避免被离线页面拦截 |

### 7.5 本地开发

- `npm run dev`：Vite 插件在本地运行 `server/router.ts`，数据库为 sql.js（文件 `.dev-data/ledger.sqlite`），行为与线上一致（登录页、鉴权、同步）。
- 首次启动自动创建开发账号，见 `dev/dev-config.ts`。
- 本机的 workerd（`wrangler pages dev` 的运行时）启动即崩溃，因此不使用 wrangler 本地模式。

## 8. 账号脚本（`scripts/create_user.py`）

```
python scripts/create_user.py [--remote | --dev | --local] [--username me] [--password-stdin] [--iterations 100000]
```

- 交互输入两次密码（不回显）；`--password-stdin` 供自动化测试从标准输入读取。
- 本地计算 PBKDF2 哈希，生成 `INSERT … ON CONFLICT(username) DO UPDATE` 语句：`--remote` 写入临时 SQL 文件后调用 `wrangler d1 execute ledger --remote --file` 执行；`--dev` 用 Python sqlite3 在事务中直接写入本地开发库。
- 同一用户名再次执行即重置密码，并清除该用户的全部会话与登录失败记录。
- 密码原文不写入文件、不出现在命令行参数中。
