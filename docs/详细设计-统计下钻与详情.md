# 个人记账 PWA —— 详细设计：统计下钻、账单详情、二级分类（v1.4）

> 依据：[需求分析与架构设计.md](需求分析与架构设计.md) 第六部分。

---

## 1. 数据模型

### 1.1 分类

`Category.parentId` 已在 v1.0 预留，这次启用：

- 只支持两级：子分类的 `parentId` 指向一级分类；一级分类没有 `parentId`。
- 子分类与父分类的 `type`（支出 / 收入）必须相同。
- 子分类的图标、颜色默认继承父分类，可以单独修改。

工具函数（`domain/category.ts`）：

```ts
rootOf(id, map): Category            // 子分类 → 一级分类；一级分类返回自身
childrenOf(parentId, list): Category[]
fullName(id, map): string            // 「交通 › 充电」
descendantIds(parentId, list): Set<string>   // 自身 + 子分类
```

### 1.2 预置分类

- 一级分类沿用原有 id（`exp-food` 等），新增 `exp-insurance`（保险）、`exp-pet`（宠物）、`exp-beauty`（美容美发）、`inc-refund`（退款）。
- 子分类 id：`<父 id>-<英文名>`，例如 `exp-traffic-charge`。
- 预置分类全部以 `updatedAt = 0`、不标记待同步的方式写入，与 v1.2 的规则相同。
- **补齐**：`ensureSeed()` 改为「按 id 补齐缺失的预置分类」，而不仅仅在分类表为空时写入。这样已有用户也能拿到新分类；用户改过名的预置分类不受影响（按 id 判断已存在即跳过）。
- 新增一级分类的排序号接在原有分类之后，「其他」保持在最后。

### 1.3 流水的导入原始字段

```ts
interface TxMeta {
  counterparty?: string;     // 交易对方
  goods?: string;            // 商品 / 商品说明
  method?: string;           // 支付方式 / 收付款方式
  status?: string;           // 交易状态（原文）
  merchantOrderNo?: string;  // 商户单号 / 商家订单号
  billType?: string;         // 微信「交易类型」或支付宝「交易分类」
  refundedFen?: number;      // 已退款金额
  autoCategoryId?: string;   // 导入时自动分到的分类，用于判断用户是否改过分类
}
Transaction.meta?: TxMeta
```

## 2. 导入的调整

- `BillRow` 新增 `method`、`merchantOrderNo`；`toTransaction` 写入 `meta`。
- 分类匹配（`classify.ts`）改为匹配到子分类：
  1. 用户规则；
  2. 关键词（细分到子分类，例如「意外」→ 意外险，「充电 / 新电途 / 特来电」→ 充电，「外卖 / 美团外卖 / 饿了么」→ 外卖，「药」→ 买药）；
  3. 支付宝自带分类 → 一级分类（如「保险」→ 保险，「宠物」→ 宠物，「美容美发」→ 美容美发）；
  4. 「其他」。
  
  关键词在支付宝自带分类之前，用于细分到子分类。但只有当关键词命中的分类和支付宝自带分类属于同一个一级分类时，才采用关键词的结果，避免误判。
- 退款（找不到原交易的）→ 收入 · 退款（`inc-refund`）。
- 重新导入时（计划中 `exists` 的记录），额外生成**补全动作**：
  - 本地记录没有 `meta` 时，补上 `meta`；
  - 分类细化：设旧分类为 `cur`，新分类为 `next`。当用户没改过分类时才细化，「没改过」的判断：有 `meta.autoCategoryId` 时为 `cur === meta.autoCategoryId`；没有时（v1.3 导入的）为 `cur` 是一级分类或「其他」。满足下面任一情况就改为 `next`：
    - `cur` 是 `next` 的父分类；
    - `cur` 是「其他」，且 `next` 不是「其他」。
  - 预览中显示为「补全详情 N 条」（其中「细化分类 M 条」），默认执行。

## 3. 账单详情页（`#/tx/:id`）

- 路由权限：`ledger.view`。
- 顶部：分类图标（大）、分类全名、金额（支出 `-`、收入 `+`，大号字体）；有退款时显示「已退款 ¥X」。
- 字段列表（没有值的行不显示）：当前状态、支付时间（`YYYY-MM-DD HH:mm:ss`）、交易对方、商品、支付方式、交易单号、商户单号、账单来源（微信支付 / 支付宝 / 手动记账）、分类、备注、记录时间（`createdAt`）。
- 单号可点「复制」（`navigator.clipboard`，不可用时提示长按复制）。
- 「分类」一行可直接点击修改（弹出两级分类选择），需要 `ledger.edit`。
- 底部按钮：编辑（进入 `#/edit/:id`）、删除；没有 `ledger.edit` 时不显示。
- 明细列表（首页、筛选页）点击流水 → 详情页；左滑删除保持不变（需要 `ledger.edit`）。

## 4. 统计下钻与筛选明细页

### 4.1 统计页

- 排行列表、环形图扇区按**一级分类**汇总；可切换「一级分类 / 子分类」两种展示。
- 点击排行项或扇区 → `#/list?month=YYYY-MM&type=expense&category=<id>`。
- 点击每日柱状图的柱子 → `#/list?day=YYYY-MM-DD&type=expense`。

### 4.2 筛选明细页（`#/list`）

| 参数 | 含义 |
|---|---|
| `month` | 月份；与 `day` 二选一 |
| `day` | 某一天 |
| `type` | `expense` / `income`，可选 |
| `category` | 分类 id；为一级分类时包含其子分类 |

```
‹  交通 · 2026年10月
────────────────────────
合计 -1,234.56 · 共 27 笔
[全部] [充电 18] [打车 6] [停车过路 3]     ← 一级分类时显示子分类筛选
────────────────────────
10月27日 周二              支出 58.00
  ⚡ 充电  新电途            -19.99
  …
```

- 列表复用 `TxDayGroup`；点击进入详情。
- 页面标题根据参数生成，例如「交通 · 2026年10月」「10月27日 支出」。

## 5. 记账页与分类管理

### 5.1 记账页的分类选择

- 宫格只显示一级分类。选中有子分类的一级分类后，下方出现一行横向滚动的子分类标签：「不细分」+ 各子分类。
- 编辑已有记录时：如果它属于某个子分类，自动选中该子分类所在的一级分类和子分类。

### 5.2 分类管理页

- 每个一级分类下缩进显示其子分类。
- 「新增分类」弹窗增加「上级分类」选项（默认「无（一级分类）」）。
- 排序按钮只在同级之间移动。
- 隐藏一级分类时，它的子分类也不在记账页显示。
- 一级分类下已有子分类时，不允许再把它设为别人的子分类（只支持两级）。

## 6. 测试要点

- 分类工具函数：rootOf、descendantIds、fullName。
- 预置补齐：空库全量写入；已有库只补缺失项，不覆盖改名。
- 分类匹配：保险细分、充电、外卖、买药；关键词与支付宝分类冲突时以支付宝一级分类为准。
- 导入补全：无 meta → 补 meta；分类细化的各种情况（一级 → 子、其他 → 具体、用户改过的不动）。
- 统计：子分类金额计入父分类；按子分类展开。
- 筛选：按月 + 一级分类（含子分类）、按天。
