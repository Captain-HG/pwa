## 2. 数据库（`0002_roles.sql`）

```sql
CREATE TABLE roles (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL UNIQUE,
  description TEXT NOT NULL DEFAULT '',
  permissions TEXT NOT NULL,              -- JSON 数组，如 ["ledger.view","ledger.edit"]；管理员为 ["*"]
  builtin     INTEGER NOT NULL DEFAULT 0, -- 1 = 预置角色，不可删除
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

INSERT INTO roles (id, name, description, permissions, builtin, created_at, updated_at) VALUES
  (1, '管理员',   '拥有全部权限',               '["*"]', 1, <now>, <now>),
  (2, '普通成员', '记账、统计、分类、导出备份', '["ledger.view","ledger.edit","stats.view","category.manage","backup.export"]', 1, <now>, <now>);

ALTER TABLE users ADD COLUMN role_id      INTEGER NOT NULL DEFAULT 2 REFERENCES roles(id);
ALTER TABLE users ADD COLUMN display_name TEXT NOT NULL DEFAULT '';
ALTER TABLE users ADD COLUMN disabled     INTEGER NOT NULL DEFAULT 0;

-- 升级前已存在的账号都设为管理员
UPDATE users SET role_id = 1;
```

> `role_id` 不声明 `REFERENCES`：D1 默认开启外键约束，SQLite 此时不允许 `ADD COLUMN` 带非 NULL 默认值的外键，由应用层保证角色存在（删除角色前检查使用人数）。

## 3. 权限模型（`shared/permissions.ts`）

```ts
export const PERMISSIONS = [
  { key: 'ledger.view',     name: '查看明细',            group: '记账' },
  { key: 'ledger.edit',     name: '记账（新增/修改/删除）', group: '记账', requires: ['ledger.view'] },
  { key: 'stats.view',      name: '查看统计',            group: '记账' },
  { key: 'category.manage', name: '分类管理',            group: '设置' },
  { key: 'backup.export',   name: '导出备份',            group: '设置' },
  { key: 'backup.import',   name: '导入备份 / 清空流水',   group: '设置', requires: ['ledger.edit'] },
  { key: 'admin.users',     name: '用户管理',            group: '系统管理' },
  { key: 'admin.roles',     name: '角色与权限',          group: '系统管理' },
];
export const ALL = '*';
export function can(perms: string[], p: string): boolean   // perms 含 '*' 或含 p
export function normalize(perms: string[]): string[]        // 去掉未知项，补齐 requires，排序去重
export const ROUTE_PERMISSIONS: Record<string, string[]>    // 路由 → 需要的任一权限
```

| 路由 | 需要（任一） |
|---|---|
| `/` 明细 | `ledger.view` |
| `/add`、`/edit/:id` | `ledger.edit` |
| `/stats` | `stats.view` |
| `/categories` | `category.manage` |
| `/backup` | `backup.export`、`backup.import` |
| `/admin/users` | `admin.users` |
| `/admin/roles` | `admin.roles` |
| `/settings`、`/account` | 无（所有人） |

## 4. 服务端

### 4.1 会话

`getSession` 联表查询 `users` 与 `roles`，返回：

```ts
interface Session { id; userId; username; displayName; roleId; roleName; permissions: string[] }
```

- `users.disabled = 1` 时，会话视为无效（返回 401）。
- 登录：密码正确但账号已停用时，返回 403「账号已停用，请联系管理员」。密码错误时仍然只提示「用户名或密码错误」。

### 4.2 接口权限

| 接口 | 需要 |
|---|---|
| `GET /api/auth/me` | 登录即可，返回 `{ id, username, displayName, role, permissions }` |
| `GET /api/sync/pull` | `ledger.view` 或 `stats.view` |
| `POST /api/sync/push` | 按实体：`transactions`、`accounts`、`budgets` 需要 `ledger.edit`；`categories` 需要 `category.manage` 或 `ledger.edit` |
| `/api/admin/users*` | `admin.users` |
| `/api/admin/roles*` | `admin.roles`；`GET /api/admin/roles` 有 `admin.users` 也可调用（新建用户时要选角色） |

无权限统一返回 403「没有权限」。

### 4.3 管理接口

| 方法 | 路径 | 请求 | 说明 |
|---|---|---|---|
| GET | `/api/admin/users` | — | `{ users: [{ id, username, displayName, roleId, roleName, disabled, createdAt, lastSeenAt }] }` |
| POST | `/api/admin/users` | `{ username, displayName, password, roleId }` | 用户名 1–32 位，只能用字母、数字和 `_ . -`，不区分大小写判断是否重复；密码至少 8 位 |
| PATCH | `/api/admin/users/:id` | `{ displayName?, roleId?, disabled? }` | 停用时删除其全部会话 |
| POST | `/api/admin/users/:id/password` | `{ password }` | 重置密码，删除其全部会话 |
| DELETE | `/api/admin/users/:id` | — | 删除用户、会话和云端账目 |
| GET | `/api/admin/roles` | — | `{ roles: [{ id, name, description, permissions, builtin, userCount }] }` |
| POST | `/api/admin/roles` | `{ name, description, permissions }` | 名称 1–20 字，不能重复 |
| PATCH | `/api/admin/roles/:id` | `{ name?, description?, permissions? }` | 管理员角色不能修改 |
| DELETE | `/api/admin/roles/:id` | — | 预置角色、正在被用户使用的角色不能删除 |

### 4.4 保护规则

```
「启用中的管理员」= disabled = 0 且角色权限含 '*'
- 修改用户角色、停用、删除前：如果被操作的用户是启用中的管理员，操作后系统里必须还剩至少 1 个 → 否则 400「至少需要保留一个启用中的管理员」
- 不能对自己执行：停用、删除、修改角色（400）
- 角色权限经 normalize 处理；含 '*' 的权限只属于预置的管理员角色，其他角色不能设置
```

写接口的 CSRF 校验扩展到 `PATCH` 和 `DELETE`。

## 5. 前端

### 5.1 当前用户（`stores/auth.ts`）

- 启动时请求 `/api/auth/me`，成功后保存到本机设置 `me`；离线时用缓存。
- `can(permission)`、`canRoute(path)`；登录用户的权限变了，菜单随之刷新。
- **本机数据归属**：本机设置 `ownerUserId` 和 `me.id` 不同 → 停止同步 → `wipeLocal()` → 重新写入预置数据 → 记录新的 `ownerUserId` → 开始同步。第一次升级时 `ownerUserId` 还没有值，直接记为当前用户，原有数据保留。
- `me`、`ownerUserId` 只属于本机，不进入备份，退出登录时清除。

### 5.2 路由守卫与菜单

- `router.beforeEach`：目标路由需要的权限不满足时，跳到第一个有权限的页面（顺序：明细 → 统计 → 设置；设置页所有人可进，因此不需要单独的「无权限」页面）。
- 首次离线启动、还没拿到用户信息时，临时只开放「查看明细、记账、查看统计」，联网后以服务端返回的权限为准。
- 底部 Tab：没有权限的 Tab 不显示；「＋」只在有 `ledger.edit` 时显示。
- 明细：没有 `ledger.edit` 时，不能左滑删除，点击记录也不进入编辑。
- 设置：「分类管理」「备份与恢复」「清空所有流水」「用户与权限」按权限显示。
- 预置分类写入时不再标记为待同步（`dirty = 0`），用户修改后才上传。这样没有分类管理权限的用户也不会因为推送预置分类而同步失败。

### 5.3 用户管理页（`#/admin/users`）

```
用户管理                         [＋ 新建]
──────────────────────────────────────
admin（我）      管理员           最近活动 刚刚
小明             普通成员         最近活动 3 天前
妈妈  已停用     只读             从未登录
```

点击用户打开弹窗：显示名、角色（单选）、启用开关、[重置密码]、[删除用户]。对自己的账号只能改显示名。

### 5.4 角色管理页（`#/admin/roles`）

```
角色与权限                        [＋ 新建]
──────────────────────────────────────
管理员    预置 · 全部权限        1 人
普通成员  预置 · 5 项权限        1 人
只读      2 项权限              1 人
```

点击角色打开弹窗：名称、说明、按分组列出的权限勾选框（勾「记账」时自动勾上「查看明细」）、[删除]。管理员角色只能查看，不能修改。

## 6. 建号脚本

```
python scripts/create_user.py --remote [--admin]
```

- 新建用户默认是「普通成员」；加 `--admin` 则设为管理员。
- 已有用户重置密码时不改变角色；加 `--admin` 时提升为管理员（用于管理员把自己锁在外面时恢复）。
