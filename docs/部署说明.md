# 部署说明：Cloudflare Pages

把 `dist/` 中的静态文件上传到 Cloudflare Pages，得到一个 HTTPS 地址，iPhone 通过它安装 PWA。
网站上只有代码，**账目数据始终只在手机本地**，别人打开同一地址只会看到空账本。

相关文件：

| 文件 | 作用 |
|---|---|
| `wrangler.toml` | Pages 项目名 `my-ledger`、输出目录 `dist` |
| `public/_headers` | 响应头：`index.html` / `sw.js` 不缓存，确保新版本能被发现；`assets/` 长期缓存 |
| `package.json` 中的 `cf:*`、`deploy` 脚本 | 见下文 |

## 一、首次部署（只需做一次）

以下命令都在项目目录 `D:\工具\记账PWA` 下运行。

### 1. 授权命令行工具

网页上登录 Cloudflare 不等于命令行已授权，需要单独授权一次：

```bash
npm run cf:login
```

会自动打开浏览器，点「Allow」授权即可。完成后可检查：

```bash
npm run cf:whoami
```

能看到你的邮箱和 Account ID 即为成功。

> 如果电脑上开着代理，wrangler 会提示 `Proxy environment variables detected`，属正常提示。若授权页面回调失败，可暂时关闭代理重试。

### 2. 创建 Pages 项目

```bash
npm run cf:create
```

成功后会输出项目地址。本项目实际地址：`https://my-ledger-evs.pages.dev`（`my-ledger` 已被占用，自动加了后缀）。
若 `my-ledger` 这个名字已被别人占用，Cloudflare 会自动分配带后缀的地址（如 `my-ledger-abc.pages.dev`），以实际输出为准。
想换名字的话，同时修改 `wrangler.toml` 的 `name` 和 `package.json` 中 `cf:create` 脚本里的项目名。

### 3. 发布

```bash
npm run deploy
```

依次执行：单元测试 → 类型检查与构建 → 上传 `dist/`。任一步失败都不会上传。
最后输出的 `https://xxxx.my-ledger-evs.pages.dev` 是本次部署的预览地址，**正式地址**是第 2 步得到的 `https://my-ledger-evs.pages.dev`。

### 4. 云端数据库与账号（v1.1 起）

只需做一次：

```bash
npm run db:create
```

创建 D1 数据库 `ledger`，并把输出中的 `database_id` 填入 `wrangler.toml`（本项目已填好）。

```bash
npm run db:migrate:remote
```

在云端建表。以后新增 `migrations/*.sql` 时再执行一次即可。

```bash
npm run user:create
```

创建登录账号：按提示输入用户名和两次密码（输入时不显示）。密码只在本机计算哈希后写入数据库。
**忘记密码**时再执行一次同名用户即可重置，并会让所有设备下线。

> v1.2 起，日常增加用户、分配角色请在应用内「设置 → 系统管理」中操作；脚本主要用于创建第一个管理员和紧急恢复（`--admin`）。

> 建议密码 12 位以上。完成后执行 `npm run deploy` 发布，打开正式地址会先出现登录页。

## 二、安装到 iPhone

1. iPhone 用 **Safari** 打开正式地址（其他浏览器无法添加 PWA）。
2. 点底部「分享」→「添加到主屏幕」→「添加」。
3. 以后**只从主屏幕图标进入**。主屏 App 与 Safari 标签页的数据相互独立。
4. 首次打开后，建议断网再打开一次，确认离线可用。

如果之前在局域网地址（`http://192.168...`）记过账，那些数据不会自动出现在这里。需要的话：局域网版「设置 → 备份与恢复 → 导出 JSON」，再在正式版里导入。

## 三、日常更新

改完代码后：

```bash
npm run deploy
```

手机下次打开 App 时会弹出「有新版本」，点「刷新」即可，数据不受影响。
若没有弹出，完全关闭 App（上滑划掉）后重新打开。

## 四、可选：再加一层 Cloudflare Access

v1.1 起站点已有登录保护，一般不需要。若想再加一层邮箱验证码：
Cloudflare 控制台 → Zero Trust → Access → Applications → 添加 `my-ledger.pages.dev`，策略设为「邮箱等于自己的邮箱」。
之后打开页面需先输入邮箱收到的验证码（免费，每 24 小时左右验证一次）。

> 注意：开启 Access 后，离线时仍可使用（Service Worker 已缓存），但更新新版本时需要先通过验证。

## 五、本地开发

```bash
npm run dev
```

打开 http://localhost:5173 ，会先出现登录页，开发账号见 `dev/dev-config.ts`。
本地用 sql.js 模拟 D1（数据在 `.dev-data/ledger.sqlite`），登录、鉴权、同步与线上是同一套代码。
需要其他本地账号时：`python scripts/create_user.py --dev`。

> 本机的 workerd 无法启动，`wrangler pages dev` 不可用，所以不走 wrangler 本地模式。

## 六、常见问题

| 现象 | 处理 |
|---|---|
| `You are not authenticated` | 重新运行 `npm run cf:login` |
| `Project not found` | 先运行 `npm run cf:create`；或项目名与 `wrangler.toml` 不一致 |
| 手机上一直是旧版本 | 完全关闭 App 后重开；仍不行可在 Safari 打开一次正式地址刷新 |
| 删除了主屏幕图标 | 重新添加并登录，数据会从云端恢复 |
| 登录后提示 `Exceeded CPU` 或 503 | 免费版 CPU 限制，执行 `python scripts/create_user.py --remote --iterations 50000` 降低迭代次数重设密码 |
| 忘记密码 | 让管理员在「用户管理」里重置；管理员自己忘记时执行 `npm run user:create`，输入同一用户名和新密码 |
| 管理员被误降级 / 停用，无法进入管理页 | 执行 `python scripts/create_user.py --remote --admin`，输入该用户名并设置新密码，会恢复为启用中的管理员 |
